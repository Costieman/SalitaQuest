# Salita Quest 5.5.3 — Level rewards run once

This Stage 1 emergency patch addresses the continuing level-up and avatar-reward loop on both the phone and computer versions of Salita Quest.

## Run-once persistence

The level-up record is now acknowledged and saved **before any animation DOM is created**. Closing the app, changing tabs, refreshing, or losing connection during an animation cannot leave the same level pending for another replay.

The stored progression record now maintains:

- levels already celebrated;
- milestone animations already shown;
- the latest acknowledgement time and release;
- a repaired pending queue limited to the learner's real calculated level.

## Avatar reward popup safety

Avatar unlock entries are also consumed and written to the learner profile before their popup appears. Duplicate entries for the same avatar reward are removed together. A durable run-once key and history record prevent an old pending entry from being reintroduced by a stale browser tab.

Existing level-milestone avatar popups already represented by the combined level animation are removed safely. Ownership, full shards, badges, XP, mastery and course progress are not removed.

## Reward artwork in the level animation

At Levels 10, 20, 30 and the later milestone levels, the level-up animation now resolves the milestone avatar from the central catalogue and displays:

- the actual avatar reward image;
- the avatar's name;
- a fallback image if the intended artwork cannot load.

The currently equipped avatar remains the animation image for non-milestone level changes.

## Phone and computer coverage

Tagalog and Bisaya loaders now request the 5.5.3 profile, level and unlock runtimes directly. The existing refresh page can be used on either phone or computer and clears only app caches and service-worker registrations. It does not clear localStorage, learner profiles or saved course progress.

Service-worker cache:

`salita-quest-v5-5-3-level-run-once-r46`

## Scope

This is Stage 1 only. The Avatar Collection visual cleanup and the three-state sticky sidebar remain separate follow-up stages.
